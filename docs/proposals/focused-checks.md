# First-release checks

Standing portfolio authorization covers this new app, its free public Ubuntu CI and first Vercel delivery. This scope uses authored disposable T2 profiles/plans and public official call metadata only. No account, credential, bank, document, model, database or paid service is created.

- Thirteen profile/plan boundaries: unknown answers, employed low-resource discovery without entitlement, rental territory exceptions, disability uncertainty, strict answers and official sources, Unicode backup, independent state, malformed/oversized/prototype import refusal, preservation and calendar format/privacy.
- Sixteen BDNS boundaries: exact public metadata, bounded pagination, malformed/oversized/duplicate refusal, one anonymous fixed request, status/redirect/JSON/UTF-8/timeout refusal and atomic last-good preservation. These use injected authored fetch responses, not a live source.
- B01 desktop: actual optional profile, source link, save, checklist, notes, progress, downloaded ICS and opt-in reload.
- B02 narrow touch emulation: actual profile/category/search navigation, an explicitly authored dated catalogue fixture, preparation state and session-only reset. No physical-device claim.
- B03 desktop: actual file input, cancelled/accepted replacement, hostile text remaining text, downloaded JSON, rejected import preserving prior state and confirmed clear.
- B04 desktop: authored blocked Storage and invalid-feed controls retain a usable memory plan and backup, with explicit removal failure.

The source guards bind tracked bytes before and after. CI installs only exact Playwright/core 1.65.0 with registry integrity pins in owned runner storage; application dependencies remain zero. The real Chromium scenarios reject console/page/request errors, external requests and profile-bearing query strings. The app server listens on loopback and is reaped by a shell trap. The 20-minute runner and disposable contexts are discarded; original reports/screenshots are retained for seven days and canonical result evidence is published separately.

The separate five-minute daily catalogue workflow makes one serialized read and conditionally updates only `public/data/calls.json` through GitHub's contents API. Its first manual execution must establish real source connectivity and public-data publication; fixtures and documentation do not substitute for that proof. Source errors leave the previous committed catalogue intact. No raw recipient or concession records are requested.
